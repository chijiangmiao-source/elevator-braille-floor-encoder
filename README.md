# 电梯标牌盲文核对器

送雕刻前的纯前端核对工具：打样人员把墨字楼层号逐行粘贴进文本框，工具按统一的
六点盲文编码规则实时生成 **Unicode 盲文串** 与 **每格六点示意（SVG）**，
用于逐点核对是否漏了数字符或地下层前缀。雕刻人员拿到实物标牌后，还可在
**实物逐点复核** 面板中逐格录入摸到的凸点，系统即时比对缺失点与多余点。

- 纯前端：TypeScript + Vue 3 + Vite，无后端、无网络请求
- 唯一编码实现位于 [`src/braille.ts`](src/braille.ts)，复核领域模块独立于
  [`src/review.ts`](src/review.ts)，点位观察方向的显示投影独立于
  [`src/projection.ts`](src/projection.ts)，页面、单元测试、端到端测试共用，
  **不存在任何固定/兜底响应**
- 测试：Vitest（点位映射、镜像投影、整批失败、楼层排序、点集差异、状态推导、
  存储校验等 95 项）+ Playwright（界面、键盘操作、施工面切换与实物复核 26 项）

## 编码约定

六点编号（从盲文读者方向，左列 1-2-3，右列 4-5-6）：

```
 1 ● ● 4
 2 ● ● 5
 3 ● ● 6
```

- 数字串前**必须**先加数字符（点 `3456`，Unicode `⠼`）；数字 1~9、0
  依次使用：

  | 数字 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 0 |
  | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
  | 点 | 1 | 12 | 14 | 145 | 15 | 124 | 1245 | 125 | 24 | 245 |

- 地下层 `Bn`（n 为 1~9）从左到右依次为：
  大写符（点 `6`，`⠠`）→ 字母 B（点 `12`，`⠃`）→ 数字符（点 `3456`，`⠼`）
  → 数字点。各单元之间**不插入空白**。
- Unicode 盲文图案块基准为 `U+2800`，点 n 对应第 n−1 个比特。

示例：

| 墨字 | 单元点序列 | Unicode 盲文串 |
| --- | --- | --- |
| `1`  | `3456 1` | `⠼⠁` |
| `10` | `3456 1 245` | `⠼⠁⠚` |
| `42` | `3456 145 12` | `⠼⠙⠃` |
| `B1` | `6 12 3456 1` | `⠠⠃⠼⠁` |
| `B9` | `6 12 3456 24` | `⠠⠃⠼⠊` |

## 核对方式（与启动后页面行为一致）

1. 每行输入一个楼层代码。合法形式**仅**为 `1`–`99` 或 `B1`–`B9`：
   - 区分大小写（`b1` 非法，必须大写 `B`）；
   - 代码内部及首尾不得有任何空白（空格、制表符等）；
   - 空行忽略；同一代码重复出现即非法。
2. **全部合法**时，页面按原行序并排显示三列：
   墨字代码、Unicode 盲文串、每格六点示意（点亮的点为实心黑点）。
   复制按钮（或 `Ctrl/⌘+Enter`）输出制表符分隔的纯文本：
   `墨字⇥盲文串⇥各格点位`（如 `B1⇥⠠⠃⠼⠁⇥6 12 3456 1`），
   与页面预览逐行逐格一致。
   “结果排列”可在**输入顺序**（默认）与**楼层顺序**（B9→B1、1→99）
   之间切换：排序只重排已编码结果，预览与复制内容同步变化，
   原行号始终指向粘贴文本，录入内容不被改写；
   刷新或经链接进入页面时回到默认的输入顺序。
3. **任一代码非法或重复**时不生成任何结果，只报告按行序遇到的
   **首个问题行号、代码原文与明确原因**（重复时还给出首次出现行）。
   修正后结果自动恢复——雕刻人员看到的始终是唯一、可核对的点位序列。

## 点位观察方向：成品阅读面 / 背面施工面

部分标牌采用透明板背面打孔，施工人员需要看到与成品阅读面**左右镜像**的
孔位模板。合法批次生成后，可在「点位视图」中切换：

- **成品阅读面**（默认）：从读者方向观察，左列 1·2·3、右列 4·5·6；
- **背面施工面**：透明板背面所见孔位，每格左右镜像，成对换位
  **1↔4、2↔5、3↔6**（同一行不变），图例与每格六点 SVG 共用同一投影结果，
  并明确标注当前观察方向。

镜像规则在 [`src/projection.ts`](src/projection.ts) 中实现为**基于既有编码单元
的显示投影**：只改变单格内部点号落在哪个物理槽位，楼层排列与格子先后
（单元顺序）完全不变。Unicode 盲文串、复制文本（含第三列点号）、
实物复核录入、差异判断与已保存进度始终使用**原始点号**，施工视图既不改写
编码也不改写已保存进度；复核面板的参考图随方向投影，录入控件与结论不变。
刷新、重新输入（输入文本变化）或出现非法批次时自动回到成品阅读面；
任何无法投影的点号都在对应格显示可见错误，而不是静默画出错误孔位。

## 实物逐点复核

合法批次生成预览后，点击 **进入实物逐点复核**：每个盲文格出现一幅可点击的
六点图，雕刻人员把在实物标牌上摸到的凸点逐格录入（再次点击取消）。
系统即时标出 **缺失点**（编码应有而未录，红色虚线空心）与 **多余点**
（不应有而录入，红色实心），并把楼层归为：

- **待核对**：尚有格子未录入；
- **吻合**：全部格已录入且与编码逐格一致；
- **不吻合**：全部格已录入但至少一格有差异。

行为约定：

- 复核记录以 **楼层代码 + 单元序号** 为键保存在 `localStorage`
  （经 [`src/review.ts`](src/review.ts) 的存储服务读取/保存契约写入），
  离开页面后重新输入同一批次即可继续当前进度；
- “结果排列”切换只改变复核面板的展示顺序，记录始终绑定原楼层，不被改写；
- 存储内容损坏、版本不识别或与当前合法批次不匹配时，放弃对应进度并给出
  可见提示，编码预览不受任何影响；修正输入后仅恢复代码与单元结构
  完全一致的记录；
- 复核状态不参与编码计算：非法批次下复核面板随结果一起隐藏，
  原有输入校验、楼层排序与复制行为保持不变。

## 本地启动与开发

```bash
npm install
npm run dev        # 开发服务器（默认 http://localhost:4173）
npm run build      # 类型检查 + 产出 dist/ 静态资源
npm run preview    # 本地静态托管构建产物
npm run test       # Vitest 单元测试
npx playwright test   # Playwright 端到端测试（自动拉起 dev server）
```

## Docker Compose（静态 Web + 一次性验收）

```bash
# 启动静态 Web，宿主端口可用 WEB_PORT 覆盖（默认 8080）
docker compose up -d --build web
#   WEB_PORT=9090 docker compose up -d --build web

# 一次性验收服务：容器内运行 Vitest + 对静态 Web 容器跑 Playwright，
# 结束即退出（退出码 0 表示验收通过）
docker compose --profile verify run --build verify
```

- `web`：多阶段构建出 `dist/`，由 nginx 静态托管。
- `verify`：一次性服务，等待 `web` 健康检查通过后，通过
  `PLAYWRIGHT_BASE_URL=http://web:80` 对真实静态站点执行全部测试，
  不存在用固定响应代替编码的旁路。
